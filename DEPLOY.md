# Загрузка сайта на reg.ru

Сайт статический: ни PHP, ни базы, ни Node на сервере не нужно. Подойдёт любой
самый простой тариф виртуального хостинга.

---

## 1. Собрать

```bash
node build.mjs                  # превью-сборка, пока домена нет
node build.mjs osta-flowers.ru  # боевая сборка под конкретный домен
```

На выходе:

| Что | Где | Зачем |
|---|---|---|
| `dist/` | папка рядом с проектом | то, что лежит на сервере |
| `osta-flowers-site.zip` | там же | этот файл заливаем в панель |
| `htaccess-copy.txt` | там же | запасная копия `.htaccess`, **на сервер не заливается** |

Требуется `node` и `cwebp` (`brew install webp`). Без `cwebp` сборка не упадёт,
но фотографии поедут тяжёлыми JPEG вместо лёгких WebP.

### Чем превью-сборка отличается от боевой

Пока домен не указан, сборка считается превью и защищает себя от чужого
внимания: в `robots.txt` стоит `Disallow: /`, в `<head>` — `noindex`,
принудительный HTTPS выключен, а в `canonical`, `og:url` и `sitemap.xml`
вместо адреса стоит `__DOMAIN__`.

Так сделано, чтобы технический адрес reg.ru не попал в Яндекс и Google
раньше настоящего домена и не начал конкурировать с ним в выдаче.
**Как только домен появится — пересоберите с ним и перезалейте**, иначе сайт
так и останется невидимым для поиска.

## 2. Залить

Корень сайта на reg.ru зависит от панели:

- **ISPmanager** — `/www/имя-домена/`
- **cPanel** — `public_html/`

Внутрь кладётся **содержимое** `dist/`, а не сама папка. Правильно, когда
`index.html` лежит прямо в корне сайта, а не в `корень/dist/index.html`.

### Через файловый менеджер (проще)

1. Панель reg.ru → раздел «Хостинг» → «Файловый менеджер».
2. Зайти в корень сайта, удалить то, что там лежит по умолчанию
   (обычно технические `index.html` или `index.php` — заглушка хостинга).
3. Загрузить `osta-flowers-site.zip`.
4. Распаковать архив прямо в этой папке, затем удалить сам архив.
5. Включить в менеджере показ скрытых файлов и убедиться, что `.htaccess`
   на месте. Если его нет — создать файл с именем `.htaccess` вручную и
   вставить в него текст из `htaccess-copy.txt`.

> Пятый шаг пропускать нельзя. Без `.htaccess` сайт откроется, но без сжатия,
> без кэша, без редиректа на HTTPS и со стандартной страницей ошибки хостинга
> вместо нашей 404.

### Через FTP

Хост, логин и пароль приходят в письме от reg.ru при заказе хостинга.
Клиент — FileZilla или Cyberduck, порт 21.

```
Хост:   ftp.ваш-домен.ru   (или IP-адрес сервера из письма)
Логин:  из письма reg.ru
Пароль: из письма reg.ru
```

Зайти в корень сайта и перетащить туда **содержимое** папки `dist/`, включая
`.htaccess` (в FileZilla: «Сервер» → «Принудительно отображать скрытые файлы»).

## 3. Домен и SSL

1. Привязать домен к хостингу в панели reg.ru и дождаться, пока обновятся
   DNS-записи. Обычно это занимает от пары минут до нескольких часов.
2. Заказать бесплатный SSL-сертификат Let's Encrypt в панели и дождаться
   выпуска — до этого момента сайт открывается только по `http://`.
3. Пересобрать сайт под этот домен и перезалить:

   ```bash
   node build.mjs ваш-домен.ru
   ```

   Эта команда подставит адрес в `canonical`, `og:url`, `og:image`, JSON-LD,
   `robots.txt` и `sitemap.xml`, откроет сайт для индексации и включит
   переадресацию на HTTPS.

**Если после этого сайт ушёл в бесконечный редирект или ругается на
сертификат** — значит, SSL ещё не выпущен. Откройте `.htaccess` и закомментируйте
(поставьте `#` в начале) четыре строки в блоке «Весь трафик на HTTPS».
Когда сертификат выпустится, уберите `#` обратно.

## 4. Проверить после заливки

- [ ] Главная открывается, фотографии на месте, красный «стебель» слева растёт при прокрутке
- [ ] `ваш-домен.ru/robots.txt` — если сборка боевая, там `Allow: /`, а не `Disallow: /`
- [ ] `ваш-домен.ru/sitemap.xml` — внутри настоящий адрес, а не `__DOMAIN__`
- [ ] `ваш-домен.ru/любая-чепуха` — открывается фирменная страница 404, а не заглушка хостинга
- [ ] `ваш-домен.ru/.htaccess` — отдаёт 404, файл не читается снаружи
- [ ] `http://ваш-домен.ru` — сам переходит на `https://`
- [ ] `www.ваш-домен.ru` — сам переходит на адрес без `www`
- [ ] Кнопки «Заказать букет» открывают WhatsApp с готовым текстом
- [ ] Телефон в шапке звонится с мобильного

Скорость и ошибки удобно проверить на PageSpeed Insights и в Яндекс.Вебмастере
(там же добавить сайт и отправить `sitemap.xml`).

---

## 5. Как обновлять потом

Править файлы прямо на сервере не надо. Порядок такой:

1. изменить исходники (`index.html`, `css/`, `js/`, `assets/`);
2. `node build.mjs ваш-домен.ru`;
3. залить свежий `dist/` поверх старого.

Адреса `css` и `js` содержат `?v=` с отпечатком содержимого файла: после
пересборки он меняется сам, и браузеры посетителей не покажут старую версию,
несмотря на годовой кэш. Если же отредактировать файл на сервере вручную,
отпечаток останется прежним — и часть посетителей будет год видеть старое
оформление.

## Что ещё стоит доделать по содержанию

Это не про загрузку, но лучше закрыть до того, как на сайт пойдут люди
(подробности — в README.md):

- **фотографии** — сейчас временные снимки с Unsplash, нужна студийная съёмка;
  после замены убрать строку «Фото: Unsplash…» из подвала;
- **составы букетов** в разделе «Витрина» — заглушки, уточнить у студии;
- **юридическая строка** в подвале — реквизитов ИП/ООО нет; для приёма
  онлайн-оплат они обязательны.
